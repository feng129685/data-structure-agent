# 数据结构智能体：后续修改检查清单

我把项目现在的情况和接下来要做的事整理在这里。你先完整看一遍再动手；如果改动会影响线上、接口、权限、教材资料或部署，先和我说一声。

## 1. 我们现在在做什么

我们做的是《数据结构》课程学习智能体网站。学生应该能顺着一条清楚的路径完成学习：

```text
提问 -> 看懂解释 -> 必要时操作动画或进入课堂 -> 做代码/练习 -> 留下学习记录 -> 获得下一步建议
```

这一阶段先把“栈和队列”做成完整、可演示、可复查的样例，再按同一标准扩展到链表、树、图、查找和排序。不要急着继续堆很多新功能。

## 2. 先弄清楚代码结构

仓库里现在有两套后端，它们不是简单的替换关系：

| 部分 | 位置 | 现在的作用 |
| --- | --- | --- |
| Node 兼容层 | `backend/node/server.js` | `frontend/index.html` 直接调用，接口是 `/api/*`，默认端口 `8791`。 |
| Spring 后端 | `backend/spring/` | Java 21 / Spring Boot 的主后端，接口是 `/api/v1/*`，默认端口 `8792`。 |

目前前端还没有完整迁移到 Spring。不要只把前端请求里的 `/api/*` 批量改成 `/api/v1/*`，两边的鉴权、返回结构和功能范围并不完全一样。改接口前先看 `contracts/openapi-v1.yaml`，一次只迁移一个完整功能。

`tools/legacy/ppt_reader.py` 目前只是一个独立的 PPT 文本提取工具，还不是网站的正式“资料导入”功能。不要直接把它接到线上，除非补齐输入校验、人工审核和导入接口。

## 3. 第一次本地检查

先同步代码，并确认没有把自己的资料、截图、数据库或 `.env` 混进改动：

```powershell
git pull origin main
git status -sb
git log -1 --oneline
```

再至少读一遍这些说明：

- `README.md`
- `backend/spring/README.md`
- `contracts/README.md`
- `docs/content-import-guide.md`
- `.env.example`

Node 页面和兼容接口：

```powershell
npm ci
Copy-Item .env.example .env
npm test
npm start
```

浏览器访问 `http://127.0.0.1:8791`。`.env` 只放自己的测试配置，不能提交。

Spring 后端：

```powershell
cd backend/spring
.\mvnw.cmd clean test
.\mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=dev
```

开发环境使用 H2；线上环境还需要独立的 MySQL、JWT、模型、邮件和远程编译配置，不能把本地开发配置直接搬上服务器。

## 4. 现在每个功能该检查什么

| 功能 | 先检查这些 |
| --- | --- |
| AI 对话 | 回答是否有课程依据、格式是否好读、加载/超时/限流/失败时是否能重试，不要假装已经回答成功。 |
| 资料中心 | 先选章节，再看该章节资料；每份资料要有来源、版本、审核状态和权限范围。 |
| 动画实验室 | 每一步都要反映真实状态变化，有播放、暂停、重置、单步或滑块控制，边界情况也要有反馈。 |
| 课堂模拟 | 单节课只围绕一个小目标；学生回答后给具体反馈，不能把标准答案或评分规则直接返回给学生端。 |
| 在线编译 | 只能调用 Piston 等远程隔离服务，不能在网站服务器本机运行用户代码。死循环、超大输出、超时和频繁请求都要受限。 |
| 登录与学习记录 | 游客能体验基础问答和公开内容；会话、进度、个人记录和教师功能必须登录后由后端校验。 |

## 5. 这轮优先做什么

### P0：先保证线上可用和安全

- [ ] 确认 `agent.feng.xx.kg` 实际连的是哪套后端，前端版本和服务器版本一致。
- [ ] 走通注册、登录、验证码、退出和密码重置；邮件失败时不能提示“已发送”。
- [ ] 游客不能看到他人的会话、学习记录、团队资料或教师数据。
- [ ] 模型未配置、网络异常、限流和流式中断时，页面能给出正常提示。
- [ ] 在线编译对死循环、超时、输出过大、并发和频率都有限制。
- [ ] 公开仓库和日志里没有 API Key、SMTP 密码、JWT 密钥、私有教材、OCR 原文、教师 PPT 或学生数据。

### P1：把“栈和队列”真正做成学习闭环

- [ ] 各有一份审核过的学习资料、一节课堂脚本、一个交互动画、一个可运行代码示例和几道练习。
- [ ] 对话解释能给出简洁的资料依据，不确定时要说明范围，不要编内容。
- [ ] 适合动画时，智能体在回复末尾询问是否生成演示；用户确认后再打开动画。
- [ ] 动画观察、课堂作答、资料浏览和代码实验能形成真实学习记录，不能只靠前端伪造“已完成”。
- [ ] 资料页保持“章节 -> 资料列表 -> 预览/下载”的路径，不要把所有内容堆在一页。

### P2：闭环稳定后再扩展

- [ ] 用同一套内容审核和动画标准扩展到链表、树、图、查找和排序。
- [ ] 再完善教师侧作业、课堂记录和学习诊断。
- [ ] 多智能体课堂、自动导入 PPT、教师大屏这类大功能，先写清输入、输出、角色、权限、数据保存方式和验收标准，再开始开发。

## 6. 按负责方向做事

### 如果你负责前端

- [ ] 对话、课堂、资料、动画、代码实验分别是独立页面或视图，不要全堆在首页。
- [ ] 首页先给提问入口、当前学习主题和一个自然的下一步。
- [ ] 保持学习工具的风格：清楚、圆角、轻松，但不要靠很多颜色、卡片和动效制造复杂感。
- [ ] 每个页面只保留一个主要操作；加载、空数据、无权限、失败、成功和完成状态都要有反馈。
- [ ] 改接口前先看 OpenAPI；改完至少检查桌面和手机页面，并附关键截图或录屏。

### 如果你负责课堂或动画

- [ ] 先从 `contracts/examples/classroom/` 和 `contracts/examples/animations/` 里的示例复制格式，不要自行发明字段。
- [ ] 每节课写清一个学习目标、3 到 4 个关键问题、至少两个常见误区和对应反馈。
- [ ] 每个动画先写清初始状态、操作序列、每一步状态和学生最终应该观察到的结论。
- [ ] 修改动画 JSON、后端校验和前端渲染时，要在同一次改动里一起验证。

### 如果你负责资料或 PPT

- [ ] 按 `docs/content-import-guide.md` 整理章节、来源、版本、授权范围和审核状态。
- [ ] 先完成一份栈资料和一份队列资料的审核样例，再批量导入。
- [ ] 资料默认标记为 `DRAFT`；审核完成后才能成为 `PUBLISHED`。
- [ ] 不要把完整教材、原始 OCR、教师 PPT、参考答案放进公开 GitHub。

### 如果你负责后端

- [ ] 改 API 形状时，先更新 OpenAPI 或 JSON Schema，再更新实现和前端。
- [ ] 资源权限、课程内容、学习证据和角色判断必须由后端最终校验，不能只靠前端隐藏按钮。
- [ ] 模型、邮件、文件、远程编译等外部服务要有超时、限流、错误映射和可排查的日志。
- [ ] 课堂脚本和动画数据都要先经过 Schema 校验，再给前端渲染。

## 7. 这些事不能碰

- 不提交 `.env`、数据库文件、私有资料、截图缓存、服务端配置或任何密钥；不要使用 `git add .`。
- 发现密钥曾进入提交历史时，要去服务商后台轮换，不能只在最新文件里删掉。
- 线上关闭 `KNOWLEDGE_DEBUG_API`，不要通过 `ALLOW_FIRST_USER_TEACHER` 给用户提权。
- 不让浏览器直接渲染模型返回的任意 HTML、JavaScript 或内联 SVG；动画只接收经过白名单和 Schema 校验的结构化数据。
- 不在 Node 或 Spring 服务器上用 shell、`ProcessBuilder` 或临时可执行文件运行用户代码。

## 8. 每次提交前都做

```powershell
git fetch origin
git status -sb
git diff --check
```

- [ ] 一个提交只解决一个明确问题，接口和数据结构改动不要顺手夹带大量 UI 重构。
- [ ] 提交前只按文件暂存，确认 `git diff --cached` 里没有敏感信息或无关文件。
- [ ] 改 Node 层后运行 `npm test`。
- [ ] 改 Spring 后端后运行：

```powershell
cd backend/spring
.\mvnw.cmd clean test
.\mvnw.cmd -DskipTests package
```

- [ ] UI 改动至少检查游客、登录学生、教师/管理员三种状态，以及正常、加载、空数据、无权限和失败场景。
- [ ] 提交说明写清“为什么改、改了什么、怎么验证、还有什么没覆盖”。

## 9. 做完一轮后这样验收

- [ ] 游客能提一个栈或队列问题、看公开资料和体验一个动画；访问个人或教师内容时会被合理引导。
- [ ] 登录学生能继续对话、进入课堂、作答、操作动画或运行代码，并在学习记录里看到真实结果。
- [ ] 教师/管理员只能看到自己有权限查看的课程、作业和学习证据，不能越权查看私人会话。
- [ ] 模型、邮件、数据库或 Piston 服务不可用时，系统不会崩溃，也不会泄露配置。

## 10. 下面这些情况先找我确认

- 要改 `/api/*` 或 `/api/v1/*` 的字段、鉴权方式或资源权限。
- 要上传教材、OCR 文本、教师 PPT、参考答案或任何可能有版权/隐私的问题资料。
- 要让服务器直接执行用户代码，或让模型输出直接作为页面脚本/HTML 渲染。
- 要做多智能体课堂、自动导入 PPT、教师大屏等跨模块功能。
- 发现密钥泄露、越权访问、任意文件读取、代码执行逃逸或学习记录可伪造。

先把“栈和队列”的完整学习体验做顺、做准、做安全，再往外扩。这比一次加很多看起来很酷的功能更重要。
