# 数据结构智能体：队友接手与优化检查清单

> 面向第一次接触项目的队友。请先通读本文件，再开始改代码或上传资料。
> 当前代码基线：以 Git `main` 分支的最新提交为准。
> 目标不是堆叠功能，而是交付一条学生能完整走通、教师能复查、团队能安全维护的学习闭环。

## 1. 我们正在做什么

这是一个面向《数据结构》课程的学习智能体网站。它希望帮助学生完成下面的过程：

```text
提出问题 -> 得到课程依据明确的解释 -> 观看或操作动画 -> 练习代码或课堂题目
-> 留下可信学习记录 -> 获得下一步复习建议
```

第一阶段不追求覆盖整本教材。团队当前应优先把“栈与队列”做成可演示、可追踪、可复核的完整样例，再按同一标准扩展到链表、树、图、查找和排序。

学生使用时应感到这是一个简洁的学习工具，而不是把聊天、课件、课堂、编译器、教师管理等所有功能挤在同一页的演示原型。

## 2. 先理解两个后端轨道

仓库同时保留了两套后端，它们的职责不同。开始修改前必须先确认你要改的是哪一套。

| 轨道 | 位置 | 当前用途 | API / 端口 | 修改注意事项 |
|---|---|---|---|---|
| 当前线上兼容层 | 根目录 `server.js` | 为现有 `index.html` 提供登录、聊天、资料、学习记录和在线执行等旧接口 | `/api/*`，默认 `8791` | 当前前端直接调用它。不要把接口名或返回结构随意改掉。 |
| 生产化主后端 | `apps/server/` | Java 21 / Spring Boot 模块化后端，负责账户、课程内容、RAG、课堂、动画、编译和学习证据 | `/api/v1/*`，默认 `8792` | 新前端尚未完成全量接入。改接口前先改 OpenAPI 合同，并同时安排前端迁移。 |

**最重要的结论：** 目前不要只把前端请求从 `/api/*` 批量替换为 `/api/v1/*`。这不是简单改前缀，两个版本的鉴权、数据结构和功能边界并不完全相同。任何迁移都要以 `contracts/openapi-v1.yaml` 为准，按模块逐步完成。

## 3. 项目已具备的能力

请把以下内容理解为“已有基础，需要验收和打磨”，不要默认它们都已在当前线上页面完整接通。

| 模块 | 已有基础 | 队友需要检查的重点 |
|---|---|---|
| AI 伴学对话 | 模型调用、课程知识检索、多轮会话、流式错误保护 | 回答是否有课程依据、格式是否适合学生阅读、失败时是否给出清楚提示。 |
| 知识库 / RAG | 私有教材 Markdown 检索、来源信息、章节上下文 | OCR 内容是否经过人工审校；绝不能把受限教材或原始 OCR 提交到公开仓库。 |
| 互动动画 | 栈、队列、链表、树、堆、哈希表、数组等结构化动画合同与服务端校验 | 每一步是否反映真实状态变化；控制器是否易懂；不能把模型返回的任意 HTML / SVG 直接插入页面。 |
| 课堂模拟 | 脚本化课堂、状态机、答题评价、典型误区反馈、会话快照 | 学生端不能看到标准答案和误区规则；课堂脚本必须先审校再发布。 |
| 在线编译 | C / Python 通过远端 Piston 沙箱执行，有限时、限流、并发限制 | 不允许在网站服务器本机执行用户代码；超时、死循环、输出过大时必须安全返回。 |
| 资料中心 | 章节、资源元数据、权限范围、受控文件流 | 用户先选章节再看资料；公开、课堂、团队资料的可见范围必须由后端控制。 |
| 登录与学习记录 | 注册、验证码、JWT、角色、会话、学习进度与证据 | 游客、学生、教师 / 管理员各自能做什么必须一致，不能只靠前端隐藏按钮。 |
| 教师侧能力 | 作业、课堂记录、学习证据和进度概览的后端基础 | 先保证学生闭环可用，再把教师页做成少而清楚的复核工具。 |

另外，根目录新增的 `ppt_reader.py` 是一个**独立的 PPT 文本提炼实验工具**，目前没有接入网站主流程。它只能从环境变量读取模型配置。不要把它当作已上线的“资料导入功能”，除非后续补齐依赖声明、输入校验、审核流程和导入接口。

## 4. 首次接手：30 分钟必做检查

### 4.1 拉取代码并确认版本

- [ ] 从仓库克隆或执行 `git pull origin main`。
- [ ] 执行 `git log -1 --oneline`，确认当前基线不早于 `82bfc35`。
- [ ] 执行 `git status -sb`，确认自己没有把本地资料、截图、数据库或 `.env` 混进改动。
- [ ] 阅读以下文件，至少知道每个边界在哪里：
  - [ ] `README.md`
  - [ ] `apps/server/README.md`
  - [ ] `contracts/README.md`
  - [ ] `docs/content-import-guide.md`
  - [ ] `.env.example`

### 4.2 本地运行最低验证

Node 兼容层：

```powershell
npm ci
Copy-Item .env.example .env
npm test
npm start
```

浏览器访问 `http://127.0.0.1:8791`。本地 `.env` 只填自己的测试配置，绝不提交。

Spring 后端：

```powershell
cd apps/server
.\mvnw.cmd clean test
.\mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=dev
```

开发模式会使用 H2 内存数据库和本地开发配置。生产环境需要 MySQL、独立的 `JWT_SECRET`、模型配置、邮件配置和远端编译服务配置，不能把本地开发设置直接搬到服务器。

### 4.3 不要跳过的安全确认

- [ ] `.env`、`.jwt-secret`、数据库文件、`knowledge/private/`、私有 PPT / PDF、OCR 原文、真实服务器配置均不进入 Git。
- [ ] 不使用 `git add .` 提交；先用 `git status` 看清文件，再按文件逐个 `git add`。
- [ ] 模型、SMTP、数据库和服务器密钥只从环境变量读取。
- [ ] 如果发现密钥曾经进入历史提交，立即到对应服务商后台轮换，而不是只在最新文件中删除。
- [ ] 线上关闭 `KNOWLEDGE_DEBUG_API`，不暴露教材检索片段。
- [ ] 不开启 `ALLOW_FIRST_USER_TEACHER` 作为线上提权方式。
- [ ] Spring 线上管理员没有默认密码。应配置 `BOOTSTRAP_ADMIN_EMAIL`，再通过正常的邮箱验证码注册流程创建首个管理员。

## 5. 优化优先级：先做什么，后做什么

### P0：上线前必须通过

- [ ] 确认 `agent.feng.xx.kg` 实际连接的是哪一套后端，以及前端版本与服务器版本一致。
- [ ] 确认未登录用户不能查看团队资料、他人会话、他人学习记录或教师管理数据。
- [ ] 确认登录、验证码发送、验证码校验、退出和密码重置能走通，并对错误邮箱、过期验证码、频繁请求给出友好提示。
- [ ] 确认模型未配置、限流、超时和流式中断时，页面不会卡死，也不会冒充已经回答成功。
- [ ] 确认在线编译的死循环、超大输出、过频请求和并发请求均被限制，且服务器没有执行用户本机进程。
- [ ] 确认任何公开 Git 提交不含密钥、私有教材、教师课件、真实文件路径或学生数据。

### P1：下一轮最值得做的学习闭环

- [ ] 以“栈与队列”为验收章节：各有一份审校资料、一节课堂脚本、一个互动动画、一个可运行代码例子和一组练习 / 误区反馈。
- [ ] 聊天回答中有“依据什么资料”的简洁来源提示，不能为了回答流畅而编造教材内容。
- [ ] 当解释动画更合适时，智能体在回复结尾提出是否生成演示；用户确认后才生成，不要在每次回答中强行弹出动画。
- [ ] 完成动画观察、课堂回答、资料浏览、代码复盘与学习进度之间的真实数据闭环。
- [ ] 资料中心采用“章节列表 -> 资料列表 -> 预览 / 下载”的三层路径，不在一个页面铺满所有卡片和正文。
- [ ] 将前端按模块接入 Spring `/api/v1/*`，每次只迁移一个完整功能域，例如先聊天再资料，而不是同时改所有请求。

### P2：闭环稳定后再扩展

- [ ] 扩展到链表、树、图、查找和排序，每个章节复用同一内容审核标准。
- [ ] 完善教师视角的作业、课堂证据和诊断摘要，不做只展示数字但无法追溯的仪表盘。
- [ ] 评估是否将 `ppt_reader.py` 改造为团队内部导入工具；其输出必须经过人工审核后才能进入知识库。
- [ ] 根据真实学生使用数据再决定是否需要更多智能体角色、多智能体讨论或复杂推荐，而不是先堆功能。

## 6. 功能逐项检查清单

### 6.1 AI 伴学对话

- [ ] 首页默认入口应是对话，而不是一屏塞满全部功能介绍。
- [ ] 回复使用短标题、段落、编号步骤和少量代码块，避免连续的 `###`、`**`、列表符号造成阅读噪声。
- [ ] 代码示例至少说明输入、关键边界条件、复杂度和预期结果。
- [ ] 对不确定或教材无依据的内容，回答应说明范围，而不是编造结论。
- [ ] 显示加载、取消 / 重试、网络失败、模型限流和超时状态。
- [ ] 游客可以体验基础问答；会话历史、学习记录和个性化进度只在登录后保存。
- [ ] 任何会话读取、删除和写入都必须由后端根据当前用户鉴权，不能相信前端传入的用户 ID。

### 6.2 互动动画实验室

- [ ] 动画只展示一个明确概念，例如“栈 push / pop”“队列入队 / 出队”“单链表头插法”。
- [ ] 每一步都同时显示当前数据状态、正在发生的操作和可观察的结论。
- [ ] 有播放、暂停、重置、单步前进 / 后退或滑块等真正可操作的控制，不只是自动播放的装饰动画。
- [ ] 动画状态与算法规则一致：例如栈只能从栈顶进出，队列遵循先进先出。
- [ ] 空结构、满结构、非法下标、重复操作等边界情况有明确反馈。
- [ ] 生成动画的 JSON 必须符合 `contracts/animation.schema.json`，并由后端校验后再传给前端。
- [ ] 页面不接收或执行模型返回的任意脚本、HTML 或内联 SVG；只渲染受白名单约束的结构化数据。
- [ ] 登录用户提交的动画观察应能保存为学习证据；游客可体验但不伪造保存成功。

### 6.3 课堂模拟

- [ ] 课堂页独立于普通聊天页，学生一眼能看出当前正在学什么、下一步要回答什么。
- [ ] 一节课只围绕一个小目标，不要让多个角色同时长篇对话导致用户找不到操作入口。
- [ ] 学生回答后能得到“正确 / 常见误区 / 需要再想一步”的具体反馈。
- [ ] 学生端响应中不能包含 `expected`、`misconceptions`、评分规则或标准答案。
- [ ] 已开始的课堂会话使用当时的脚本快照；修改新版本脚本不能改变历史会话。
- [ ] 新脚本先验证 `contracts/classroom-script.schema.json`，再导入，最后由内容负责人审核发布。
- [ ] 课堂状态只允许按既定状态机推进，暂停、继续、结束、重复回答都要测试。

### 6.4 资料中心和知识库

- [ ] 先让学生选择章节，再展示该章节资料。卡片只放标题、类型、学习用途和预计时长，不堆整页正文。
- [ ] 每份资料都有来源、版本、审核状态、授权范围和适用章节。
- [ ] `DRAFT` 资料不能被学生或游客读取；资源及其所属章节都必须为 `PUBLISHED` 才能对外提供。
- [ ] 游客只看 `PUBLIC`；学生增加 `CLASSROOM_ONLY`；教师 / 管理员才看 `TEAM_ONLY`。
- [ ] 前端只使用受控内容地址 `/api/v1/resources/{id}/content`，不显示服务器真实磁盘路径。
- [ ] 所有私有教材、OCR 原文、教师 PPT、参考答案和授权材料保存在团队私有目录或私有仓库。
- [ ] OCR 结果进入 RAG 前必须人工抽查高频章节，尤其是线性表、栈队列、树、图、查找、排序。

### 6.5 在线 C / Python 编译

- [ ] 对用户说明支持的语言、输入方式、运行结果和错误信息，但不要暴露沙箱服务内部配置。
- [ ] 代码执行始终经过 Piston 等远端隔离服务，禁止在 Node 或 Spring 宿主机用 shell、`ProcessBuilder` 或临时可执行文件运行用户代码。
- [ ] 测试死循环、递归爆栈、超大输入、超大输出、编译错误、运行错误和远端服务不可用。
- [ ] 限制单次代码长度、输入长度、输出长度、运行时间、单用户并发量和 IP 请求频率。
- [ ] 游客运行结果不可写成可信学习记录；登录用户的代码分析应以服务端保存的 `runId` 为准。

### 6.6 登录、邮件和权限

- [ ] 注册、登录、验证码、重置密码、退出、会话过期和重复请求均有可理解的界面反馈。
- [ ] 邮件发送失败时不能假装“验证码已发送”。本地开发可用受控回显，线上必须关闭回显。
- [ ] 角色判断由后端完成。教师按钮隐藏只能改善体验，不能代替授权校验。
- [ ] 不要创建公开文档里的默认管理员账号 / 密码。
- [ ] 生产 Cookie、CORS、SMTP TLS 和 JWT 配置使用 `apps/server/README.md` 中的说明逐项核对。

## 7. 前端体验统一检查清单

当前产品希望保持“适合学习、偏可爱、圆角但不幼稚”的风格。重点是清楚和克制，而不是用更多颜色、卡片和动效掩盖内容结构问题。

- [ ] 顶部或侧边导航只保留学生高频入口：对话、课堂、资料、动画、代码实验；教师入口按角色显示。
- [ ] 每个入口进入独立页面或独立视图，不把所有模块纵向堆在首页。
- [ ] 首页第一屏直接给出提问入口、当前学习主题和一个自然的下一步，不做冗长产品介绍。
- [ ] 卡片、输入框、弹层保持统一圆角、边框、阴影、间距和按钮状态；不出现不同模块各用一套配色。
- [ ] 同一屏的主操作只保留一个，例如“发送问题”“开始实验”“进入课堂”，避免多个相同权重的醒目按钮互相抢注意力。
- [ ] 资料、课堂和动画页删掉重复说明、装饰性标签和很长的默认文本，让学生先看任务，再按需展开解释。
- [ ] 字体层级稳定：页面标题、模块标题、正文、辅助文字、代码字体各有固定用途；不使用过多字号和粗细。
- [ ] 所有状态都有反馈：空数据、加载、错误、无权限、操作成功、已完成、重新开始。
- [ ] 在手机和 1366px 左右桌面宽度分别检查：文字不溢出，侧栏可收起，控制器可点击，代码和表格可横向滚动或重排。
- [ ] 动效只用于解释状态变化、页面切换和重要反馈；支持减少动态效果的用户不应被强制观看长动画。

## 8. 内容和合同：谁改，怎么改

### 资料 / PPT 负责人

- [ ] 按 `docs/content-import-guide.md` 整理章节、来源、版本和授权范围。
- [ ] 先完成一份栈资料和一份队列资料的审核样例，再批量导入。
- [ ] 对每份内容标记 `DRAFT`，完成审核记录后再发布为 `PUBLISHED`。
- [ ] 不把完整教材、原始 OCR、教师课件或参考答案放入公开 GitHub。

### 课堂模拟负责人

- [ ] 从 `contracts/examples/classroom/stack-lesson.json` 与 `queue-lesson.json` 复制格式，不自行发明字段。
- [ ] 每节课设计一个明确学习目标、2 至 4 个关键问题和至少两个常见误区反馈。
- [ ] 把每个问题关联到资料、动画或代码示例，避免课堂只是多轮文字聊天。
- [ ] 运行合同相关测试：

```powershell
cd apps/server
.\mvnw.cmd "-Dtest=ContractExampleCompatibilityTest,ClassroomScriptParserTest" test
```

### 动画负责人

- [ ] 以 `contracts/examples/animations/` 中的样例为起点。
- [ ] 每个新动画先写清楚“初始状态、操作序列、每一步状态、学生要观察到的结论”。
- [ ] 修改 JSON 合同、后端校验器和前端渲染器时，必须在同一个任务中同步验证。

### 前端负责人

- [ ] 先决定本次是在优化 Node 线上页面，还是在接入某个 Spring API 模块；不要混合两件事。
- [ ] 接 API 前先查看 `contracts/openapi-v1.yaml`，把接口状态、加载、错误和权限状态设计完整。
- [ ] 改动后提供桌面和手机截图，以及至少一段关键流程录屏或操作说明。

### 后端负责人

- [ ] 任何 API 形状变化先更新 OpenAPI / JSON Schema，再更新实现和前端。
- [ ] 课程内容、资源访问、学习证据和权限均由后端最终校验。
- [ ] 对模型、邮件、文件、沙箱等外部依赖提供超时、限流、错误映射和可观察日志。

## 9. 每次提交前的质量门槛

### 所有人通用

- [ ] 一个提交只解决一个明确问题。大功能拆成小的、可以独立运行和审查的改动。
- [ ] 先 `git fetch origin`，再确认不是基于过期分支开发。不要用 GitHub 网页上传一个旧目录覆盖整个仓库。
- [ ] 不使用强制推送覆盖队友提交；出现分叉时先拉取、审查、合并有效改动。

## 10. 交付前的最终验收场景

完成一轮优化后，请至少从下面四个视角各走一遍完整流程。

### 游客

- [ ] 能进入首页、提出一个栈或队列问题、得到清晰回答。
- [ ] 能看到公开资料和一个动画体验。
- [ ] 尝试进入个人记录、团队资料、教师功能时得到合理引导，而不是报错或看到不该看的数据。

### 登录学生

- [ ] 能注册 / 登录，继续历史对话。
- [ ] 能进入课堂、作答、收到反馈，完成动画观察或代码实验。
- [ ] 能在学习记录中看到与本次操作对应的真实进度，而不是前端虚构的“已完成”。

### 教师 / 管理员

- [ ] 能看到自己有权限查看的课堂、作业和学习证据。
- [ ] 能区分学生的自报事件与后端产生的可信证据。
- [ ] 不能访问其他用户的私密会话或不属于自己权限范围的资料。

### 运维 / 安全

- [ ] 生产环境密钥不在仓库、页面、日志或错误响应中出现。
- [ ] 模型、邮件、数据库和 Piston 服务不可用时，系统有受控错误而不是崩溃。
- [ ] 线上域名、CORS、Cookie 安全设置、数据库备份和日志轮转已记录在部署说明中。

## 11. 遇到以下情况先停下沟通

- 需要改变 `/api/*` 或 `/api/v1/*` 的字段、鉴权方式或资源权限。
- 想把教材、教师 PPT、OCR 文本或学生数据上传到公开仓库。
- 想让服务器直接编译 / 运行用户上传的代码。
- 想把模型输出的 HTML、JavaScript、SVG 或课堂答案直接交给浏览器执行 / 渲染。
- 想新增“多智能体课堂”“自动导入 PPT”“教师大屏”等大功能，但尚未写清输入、输出、角色、权限、数据保存与验收方式。
- 发现密钥泄露、越权访问、任意文件读取、用户代码逃逸或学习记录可伪造。

这些问题会跨模块影响安全和课程可信度，应先把问题、复现步骤和期望行为发给后端负责人 / 项目负责人，再决定实现方案。

## 12. 给队友的一句话工作原则

先把一个学生在“栈与队列”章节里从提问、理解、操作到复盘的体验做顺，再扩展功能；先让后端和内容规则保证正确与安全，再用前端把它做得简单、清楚、愿意使用。
