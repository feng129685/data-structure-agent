# 后端 API 与能力矩阵

更新时间：2026-08-11。此矩阵只以当前工作树中的路由、Controller、服务实现、Flyway 迁移、OpenAPI、fixtures 和测试源码为证据；不会把旧文档中的“已部署”描述当作本次部署事实。

## 口径与状态

- `可用`：当前源码中有可达路由或服务能力，并有契约或测试源码证据。它不等同于生产已部署。
- `兼容`：为旧前端保留的 Node `/api/*` 能力，不是 Spring v1 的等价替换。
- `缺失`：当前没有对应的公开服务端能力或受控状态接口。
- `废弃候选`：仍被旧前端调用，但不能作为新前端或正式学习闭环的主路径。
- `阻塞`：路由虽存在，却受到已知安全、代理或实现边界阻碍，不能按正式能力宣称。
- 本文中“测试”表示测试源码或契约检查已存在。本轮实际执行 Node 核心回归 `86/86`、Spring `244/244`、生产配置验证、镜像构建、生产预检与公网 smoke，结果均通过。
- `v1.0.16-structify` 已发布。逐行“部署”表示代码随该 release 上线，不等同于每个鉴权业务流程均使用真实生产账户重新操作；本轮生产验证覆盖双域首页/健康、精确 Origin CORS、未登录管理员 capability `401`、容器与备份状态。

Spring 的受控错误统一为 `ApiError { code, message, requestId, details }`；Node 兼容层主要返回 `{ error }` 或 `{ ok, ... }`，没有同一套 `requestId` 错误契约。

## 服务边界与前端选择

| 维度 | Node 兼容服务 | Spring v1 服务 |
|---|---|---|
| 源码入口 | `backend/node/server.js`，默认 8791 | `backend/spring`，默认 8792 |
| 公共路由族 | `/api/*`、`/healthz`、`/presentation/*`、`/pdfs/*` | `/api/v1/*`；`/actuator/health` 仅本机健康检查 |
| 当前职责 | 旧工作台托管、旧身份/会话、教师任务、PPT 运行时、旧聊天/执行兼容 | 已审核课程资源、知识检索、课堂、DSVP 证据、代码实验、学习记录、管理员用户/审计 |
| 代理事实 | Caddy 的 `@legacy_api` 将 `/api/*` 发到 Node；根页面也由 Node 托管 | Caddy 的 `@spring_api` 将 `/api/v1/*` 发到 Spring；`/api/v1/chat/stream` 单独关闭缓冲 |
| 前端选择 | 现有 `frontend/index.html` 仍调用大量 `/api/*` 路由 | 现有页面已调用知识检索与动画的一部分 v1 路由；后续 Vite/Vue 客户端必须通过环境变量选择完整工作流，不能把 Node 响应直接当作 Spring 响应 |
| 认证边界 | Node Bearer token 是独立 HMAC token，7 天 TTL，不含权威角色或禁用状态 | Spring Bearer JWT 或 `ds_session` cookie；每次请求从 Spring 数据库重取 active 用户及角色 |
| 过渡兼容 | 不适用 | 启用 `NODE_COMPAT_ENABLED=true` 时，只接受 Node Bearer token 访问 `GET /learning/progress`、`POST /learning/events`、`POST /animations/simulate`、`POST /animations/{id}/observations`；已有 Spring 账号仅使用数据库角色，缺失账号只镜像为 `STUDENT`，不会隐式授予教师或管理员 |

`deployment/Caddyfile.production` 与 Spring 自身 CORS 配置都允许 `PATCH`，可承载管理员用户变更的浏览器预检。生产 smoke 已验证公开与管理 Origin 的预检；管理员写入仍需真实管理员会话单独验收。

### 管理端域名发布边界

- 管理端浏览器 Origin 固定为 `https://admin.structify.cn`；学习站保留 `https://structify.cn`。Node、Spring、Caddy 和生产环境文件只接受这两个精确 Origin，未知 Origin 不返回凭据型 CORS 头。
- `admin.structify.cn` 与学习站复用同一份 Node/Spring 反向代理规则；`/api/v1/admin/*` 仍由 Spring 的数据库当前角色强制鉴权，域名本身不授予管理员权限。
- `scripts/smoke.sh` 已在 `v1.0.16-structify` 发布后通过：管理域首页和健康正常，该 Origin 的管理员 API 预检正确，未登录 `GET /api/v1/admin/capabilities` 返回 `401`。DNS 未在本次发布中修改。
